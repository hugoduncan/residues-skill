## Result

- 124 stressors: 112 generated, 12 added in the coverage step, then split: 93 training, 31 test (seed 202611062).
- Coupling at the default limits: 2 pairs, both already in the design. The sensitivity check found one hidden pair at similarity 0.3: capability probe–loader. Both define classes through Clojure's `DynamicClassLoader`.
- Adaptation: 11 changes (C01–C11), 11 open decisions. The naive design fails 15 of 93 training stressors. The adapted design still fails 3 (all absurd).
- Evaluation: S = 31, N = 28, R = 28, **Ri = 0.00**, limits −0.90 to 0.10. No regressions. 8 uncertain decisions.

## Observations

- **More stressors did not raise the Ri maximum.** The naive design survives 90% of the test stressors (r1: 89%). The maximum of Ri is the share of test stressors that the naive design fails, and that share does not depend on the number of stressors. S − N = 3 < 5, so Ri cannot show an effect again. About 50 test stressors (200 in total) are needed to get S − N ≥ 5 at this failure rate.
- **The binary decision hides graded gains.** The evaluator saw an earlier fallback or a smaller fix boundary in 5 test stressors (S045, S046, S048, S084, S092). The count does not show these.
- **The adapter was stricter than the evaluator.** On a Clojure version that is not supported, the naive code fails with "Fix: use Clojure 1.12". The criteria count a clear failure that names the fix as survival. The evaluator applied this (S045). The adaptation did not (S039, S097), so C01 deals with failures that the criteria do not count. The adaptation used the rule for S051, S055 and S118, but not for the compiler stressors.
- **The coverage step and the split can work against each other.** Coverage added two stressors for `expansion-transfer`. The random split put both in the test set, so the element has no training stressor.
- **The sensitivity check worked as written.** No hidden pair at the default limits; one at 0.3. The adaptation used it (C01 puts all class definition in one boundary). No training stressor broke this link.
- **Failures are in the same places as in r1.** The naive design fails on compiler and JVM-format change, on release security, and on silent JVM defects. Both evaluations give 0.00.
- **A code fact in r1 was wrong.** r1 adaptation S34 assumed that the field probe reports "unavailable" when `NullRestricted` disappears. The probe throws ("accepted null") instead.
